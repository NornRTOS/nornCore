Stack sizes

From the port (README "Stacks"): RTOS_STACK_MIN is the technical minimum the kernel accepts, enough for the kernel and the port plus a few frames of the task's own and meant for very simple tasks whose use has been measured; RTOS_STACK_DEFAULT is the size to start from; RTOS_STACK_LARGE is the recommended starting size for tasks that print, nest calls or use floating point, not an upper bound: a deep enough call chain or a crypto or network task needs more (tc12 shows 32 nested frames alone take 1.4 KB on the ESP32).

The minimum is not a promise that every application works with it. Measure with rtos_getStackFree, the stack monitor, tc11 and tc12.

Detailed Description

Public API of the nornOS kernel.

A fixed, compile-time known set of tasks, one unique priority per task (the task id is its priority, 0 is the implicit idle task, a higher id means a higher priority), a ready bitmask scheduler, a tick driven wake-up list sorted by time, per-task event flags, counting semaphores and immediate-priority-ceiling mutexes. The kernel is written in C99 and talks to the hardware only through the port layer (port.h).

Calling contexts
The rule for the whole API: a function without a FromIsr suffix is for task context and may block or switch task at once. Inside an RTOS_ISR body, a software timer callback running in the tick (RTOS_CFG_TIMER_TASK_PRIO 0) and the trace hook, only these are allowed: the *FromIsr variants, rtos_timerStart(), rtos_timerStop(), rtos_getTick(), rtos_getTimeUs(), the plain readers (rtos_queueCount(), rtos_mboxIsFull(), rtos_poolFreeCount(), rtos_evgroupGet(), rtos_timerIsActive(), rtos_timerRemaining()) and rtos_panic(). They never block and never switch; the switch happens once at the end of the ISR. The idle task (the context of rtos_start() and the idle hook) must never block either: a blocking call from it panics with RTOS_PANIC_ARGUMENT.
Task ids
Task ids are 1 to RTOS_CFG_NUM_TASKS. Every function that takes one checks it with RTOS_CHECK (compiled in every configuration, RTOS_PANIC_ARGUMENT on failure); the diagnostics accept the idle task 0 as well, and rtos_getTaskInfo() reports an invalid id by returning false instead.
Two kinds of checks
"Checked" in this documentation means RTOS_CHECK: always compiled, a violation is rtos_panic() with RTOS_PANIC_ARGUMENT. "Asserted" means RTOS_ASSERT: compiled only with RTOS_CFG_ASSERT, a violation calls rtos_assertFailed(). Without RTOS_CFG_ASSERT an asserted contract that is broken is undefined behaviour.
Timeouts
Every timeout is in ticks: RTOS_NO_WAIT polls, RTOS_FOREVER never times out, any other value must be at most RTOS_MAX_TIMEOUT (checked). RTOS_MS() converts milliseconds.
