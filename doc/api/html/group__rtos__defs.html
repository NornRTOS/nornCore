Stack sizes

From the port (README "Stacks"): RTOS_STACK_MIN is the technical minimum the kernel accepts, enough for the kernel and the port plus a few frames of the task's own and meant for very simple tasks whose use has been measured; RTOS_STACK_DEFAULT is the size to start from; RTOS_STACK_LARGE is the recommended starting size for tasks that print, nest calls or use floating point, not an upper bound: a deep enough call chain or a crypto or network task needs more (tc12 shows 32 nested frames alone take 1.4 KB on the ESP32).

The minimum is not a promise that every application works with it. Measure with rtos_getStackFree, the stack monitor, tc11 and tc12.

◆ RTOS_MAX_TIMEOUT

#define RTOS_MAX_TIMEOUT   ((rtos_tick_t)(RTOS_FOREVER >> 1))

The longest finite timeout, timer delay or period, periodic wait and watchdog interval in ticks: half the range of the tick type (32767 ticks with 16 bit ticks, about 32.7 s at 1 kHz; 2^31 - 1 with 32 bit ticks, about 24.8 days).

The kernel compares tick values as signed differences, which is what lets the counter wrap freely, and that only works within half the range. A larger value (other than RTOS_FOREVER) is a contract violation: RTOS_PANIC_ARGUMENT. rtos_delay is the exception: it takes any value and splits a longer delay into waits of at most this length.

Software timer callback.

enum rtos_panicReason

Why the kernel stopped the system; the first field of rtos_panicInfo_t.

Enumerator
RTOS_PANIC_NONE 
RTOS_PANIC_ASSERT 

pFile/line: the failed RTOS_ASSERT.

RTOS_PANIC_STACK_OVERFLOW 

arg1: the task whose stack bottom was overwritten.

RTOS_PANIC_WATCHDOG 

arg1: task that did not check in, RTOS_NO_TASK: idle.

RTOS_PANIC_DEADLOCK 

arg1: task that would block, arg2: task it waits for.

RTOS_PANIC_FAULT 

CPU exception; arg1: cause, arg2: address (port).

RTOS_PANIC_CONFIG 

rtos_init: the application was compiled against another configuration than the kernel; arg1: the application's signature, arg2: the kernel's (RTOS_CONFIG_SIGNATURE).

RTOS_PANIC_ARGUMENT 

A mandatory check refused an argument or an input that would corrupt memory (RTOS_CHECK in rtos_assert.h, compiled in every configuration): a task id out of range, a stack too small, a NULL storage or callback, a foreign block freed; arg1 and arg2 name the values.

RTOS_PANIC_APPLICATION 

rtos_panic called by the application; args are its own.
