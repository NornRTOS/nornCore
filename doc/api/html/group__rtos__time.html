◆ rtos_delay()

void rtos_delay ( rtos_tick_t ticks)

Blocks the calling task for at least ticks ticks.

The task wakes on the tick ticks + 1 from now, so the real delay is between ticks and ticks + 1 tick periods. A delay of 0 waits for the next tick: it is not a yield.

Parameters
ticksDelay in ticks; any value. RTOS_FOREVER blocks for good: nothing can wake the task again. A delay of RTOS_MAX_TIMEOUT or more is done as a sequence of waits, each of which may add up to one tick.
Context
Task only, not the idle task (checked).
See also
rtos_waitPeriodic(), RTOS_MS()

◆ rtos_getTick()

rtos_tick_t rtos_getTick ( void )

Returns the number of ticks since rtos_start().

The counter is RTOS_CFG_TICK_BITS wide and wraps (16 bits: after 65.5 s at 1 kHz; 32 bits: after 49.7 days). Compare tick values as differences, never directly.

Returns
The current tick count.
Context
Task, ISR body or timer callback.
See also
rtos_getTimeUs(), RTOS_MS()

◆ rtos_waitPeriodic()

bool rtos_waitPeriodic ( rtos_tick_t period)

Blocks the calling task until its next period boundary.

Each boundary is the previous boundary plus period, so the task runs drift free regardless of its execution time. The first boundary is the start of the task plus period.

If the boundary has already passed (an overrun), the call returns at once, counts the overrun (rtos_getOverrunCount()) and the next boundary is computed from now. A task whose start up work takes longer than one period therefore sees an overrun at its first call; that is harmless.

Parameters
periodPeriod in ticks, 1 to RTOS_MAX_TIMEOUT. It may change from call to call.
Returns
true if the boundary had already passed (overrun), false after a normal wait.
Context
Task only, not the idle task.
Warning
Checked: a period of 0 or above RTOS_MAX_TIMEOUT panics with RTOS_PANIC_ARGUMENT.
See also
rtos_getOverrunCount(), rtos_delay()
