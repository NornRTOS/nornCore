◆ rtos_mutexLock()

void rtos_mutexLock ( rtos_mutex_t * pMutex)

Locks the mutex.

The caller's effective priority is raised to the ceiling while it holds the mutex, so no other task that uses the mutex can run in between. With a correct ceiling the call therefore never blocks. If the mutex is held anyway (ceiling too low, or the owner blocked while holding it), the caller waits without a timeout and the unlock hands the mutex over to the highest priority waiter.

Parameters
pMutexThe mutex.
Context
Task only, not the idle task (asserted).
Precondition
The caller does not hold the mutex already: it is not recursive (asserted).
The caller's priority is at most the ceiling (asserted).
Warning
A wait that would close a cycle of tasks waiting for each other's mutexes panics with RTOS_PANIC_DEADLOCK (arg1: the caller, arg2: the owner).
See also
rtos_mutexUnlock()

void rtos_mutexUnlock ( rtos_mutex_t * pMutex)

Unlocks the mutex.

The caller's effective priority drops back to what it was before the lock. If a task waits, it becomes the owner at once, at the ceiling. Either change may let another task run before this function returns.

Parameters
pMutexThe mutex.
Context
Task only.
Precondition
The caller owns the mutex (asserted).
When holding several mutexes, unlock in the reverse order of locking (asserted).

rtos_mutexLock()
