◆ rtos_wdtInit()

void rtos_wdtInit ( uint32_t timeoutMs)

Starts the hardware watchdog.

The idle task kicks it, after checking that every monitored task checked in on time. A late task causes RTOS_PANIC_WATCHDOG with a record; a starved idle task (a runaway task or an interrupt storm) lets the hardware reset the system without one, which the next boot sees as RTOS_RESET_WATCHDOG.

Parameters
timeoutMsHardware timeout in milliseconds, above 0 (asserted); rounded up to what the hardware offers.
Note
The idle task kicks only after rtos_start(): called earlier, the start up must finish within the timeout.

rtos_wdtMonitor(), rtos_wdtCheckIn()

◆ rtos_wdtMonitor()

void rtos_wdtMonitor ( uint8_t task,
rtos_tick_t maxInterval )

Requires a task to call rtos_wdtCheckIn() at least every maxInterval ticks.

The first deadline is maxInterval from now. The check runs in the idle task, so a late task is reported when the idle task next runs.

Parameters
taskThe task, 1 to RTOS_CFG_NUM_TASKS (checked).
maxIntervalLongest allowed time between check-ins in ticks, at most RTOS_MAX_TIMEOUT (checked); 0 stops monitoring the task.
Context
Task.
